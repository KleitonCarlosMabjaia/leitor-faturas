API do Dobra

Versão 1 · contrato OpenAPI (JSON)

Para que serve

Ligar outros programas aos dados da sua empresa no Dobra: levar as faturas e os lançamentos para um ERP ou para o Power BI, ou enviar movimentos bancários de outro agregador para a reconciliação.

Autenticação

Um administrador cria a chave na página Equipa, em API e integrações. A chave pertence a uma empresa e tem permissão só de leitura ou de leitura e escrita. Envie-a em todos os pedidos:

curl https://o-seu-endereco/api/v1/empresa \
  -H "Authorization: Bearer dobra_..."
  • Guarde a chave como uma palavra-passe. Pode revogá-la a qualquer momento: o acesso termina logo.
  • Há um limite de pedidos por minuto e por chave. Acima dele a resposta é 429, com o cabeçalho Retry-After.
  • As listas são paginadas com pagina e por_pagina (até 200). A resposta traz dados e total.
  • Datas em AAAA-MM-DD, montantes em euros. Os erros vêm sempre em JSON: {"detail": "mensagem"}.

Respostas de erro

CódigoQuando
401Chave em falta, inválida ou revogada.
402Subscrição com pagamento em falta: a empresa só pode consultar.
403A chave não tem permissão de escrita, ou o plano da empresa não inclui esses dados.
404O documento não existe nesta empresa.
409O pedido não respeita uma regra contabilística (ex.: conta que não é de bancos).
422Dados inválidos (o campo detail indica qual).
429Demasiados pedidos: espere os segundos indicados em Retry-After.

Webhooks

Em vez de perguntar à API de minutos a minutos, o seu programa pode receber um aviso quando há novidades. O administrador da empresa adiciona o endereço (https) em Equipa › API e integrações › Webhooks, escolhe os eventos e recebe um segredo, mostrado uma única vez.

EventoQuando
fatura.carregadaUma fatura de compra foi carregada (ainda por rever).
fatura.confirmadaUma fatura de compra foi confirmada.
venda.registadaUma fatura emitida foi registada (manual ou do SAF-T de faturação).
lancamento.criadoFoi criado um lançamento contabilístico (incluindo estornos).
movimentos.importadosEntraram movimentos bancários (extrato, ligação ao banco ou API).
testeAviso enviado pelo botão «Testar».

Cada aviso é um POST em JSON com o evento e o identificador; os detalhes obtêm-se pela API (campo url):

POST https://o-seu-programa.pt/webhooks/dobra
Dobra-Evento: fatura.confirmada
Dobra-Entrega: 123
Dobra-Assinatura: t=1764000000,v1=5f2b…

{"id": 123, "evento": "fatura.confirmada", "criado_em": "2026-11-24T10:00:00",
 "dados": {"id": "a1b2c3d4e5f6", "url": "/api/v1/faturas/a1b2c3d4e5f6"}}

Verificar a assinatura: calcule o HMAC-SHA256 de t + "." + corpo (o corpo tal como chegou, sem o voltar a formatar) com o segredo e compare com v1. Recuse avisos com mais de 5 minutos (t), para evitar repetições. Em Python:

import hashlib, hmac, time

def aviso_valido(corpo: bytes, cabecalho: str, segredo: str) -> bool:
    partes = dict(p.split("=", 1) for p in cabecalho.split(","))
    if abs(time.time() - int(partes["t"])) > 300:
        return False
    esperada = hmac.new(segredo.encode(), f"{partes['t']}.".encode() + corpo, hashlib.sha256).hexdigest()
    return hmac.compare_digest(esperada, partes["v1"])

Responda com um código 2xx em menos de 10 segundos. Se falhar, o Dobra volta a tentar após 1 minuto, 5 minutos, 30 minutos, 2 horas e 12 horas; um endereço com 20 falhas seguidas é desativado (volta a ficar ativo com um teste bem-sucedido). O mesmo aviso pode chegar mais do que uma vez: use Dobra-Entrega para ignorar repetidos.
